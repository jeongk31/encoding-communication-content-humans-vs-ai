# Encoding of Communication Content in Experiments: Humans versus AI

Replication code and data for comparing **LLM** and **human research-assistant** coding of free-text
communication in economic experiments. Across three experiments, participant/manager messages are
classified into content categories by three LLMs (OpenAI GPT, Google Gemini, DeepSeek) under several prompt
variants, and by human coders. We then test whether the **downstream statistical results** of each study
replicate when the communication-content variables are produced by LLMs instead of humans.

## Repository layout

```
.
├── llm_coding/                 # Code that called the LLM APIs to produce the codings
│   ├── Legitimacy/
│   │   ├── llm_code_first_sessions/   # original sessions; variants: no_examples, with_examples, guidance, prompt_generation
│   │   └── llm_code_new_sessions/     # additional sessions; same four variants
│   ├── Promises/                      # variants: no_examples, examples, prompt_generation
│   └── Timing/                        # variants: no_examples, examples, guidance, prompt_generation
├── data/
│   ├── master_dataset.csv             # final merged long-format dataset — all studies/coders (Git LFS)
│   └── master_dataset_README.txt      # data dictionary (columns + per-study category definitions)
└── analysis/                          # Stata cross-study comparison tables + rendered outputs
    ├── LLM_Baseline/{simplified,extended}/    # LLM column = Base prompt
    └── LLM_Guidance/{simplified,extended}/    # LLM column = Guidance prompt (Promises falls back to Base)
```

`master_dataset.csv` is the single source of truth: one row per (episode × category × coder), with the
coder identified by `Coder_Type`, `Encoder`, and (for LLMs) `LLM_Version` and `LLM_Run`. The three coding
sources used in the analysis are **Original RA**, **New RA**, and **LLM**. Column and category definitions
are in [`data/master_dataset_README.txt`](data/master_dataset_README.txt).

## The three experiments

| Study | Coding task | Categories |
|-------|-------------|-----------|
| **Legitimacy** | Manager messages in a five-player weak-link ("turnaround") game | 11 multi-label binary: suggested effort 0/10/20/30/40 (1a–1e), ambiguous suggestion (1f), explanation (2), trust (3), positive feedback (4), negative feedback (5), social banter (6) |
| **Promises** | Pre-play messages from Player B in a trust game | One of: Promise (P), Empty Talk (E), No Message (N) |
| **Timing** | Three-player divide-the-dollar bargaining chat | 4 binary per speaker: Minimum Winning Coalition, All-way split, Compete, Future coalition |

## LLM prompt variants

Each study was coded under several prompt designs to isolate the effect of prompt content. In
`master_dataset.csv` these are the `LLM_Version` values:

- **Base** (`llm_code_no_examples`) — category descriptions only; each message coded independently.
- **Ground Truth** (`llm_code_with_examples` / `llm_code_examples`) — descriptions plus worked YES/NO examples.
- **Guidance** (`llm_code_guidance`) — *Legitimacy and Timing only.* Period context is supplied: all chatgroup
  messages for one (session, period) are sent together so messages that refer back ("same as before",
  "again") can be coded from the surrounding messages. *Promises has no Guidance variant.*
- **Self Prompt** (`llm_code_prompt_generation`) — the coding prompt is generated by the model itself.

Every variant runs three models (GPT, Gemini, DeepSeek), temperature 0, with light rate-limiting.

> **Naming note.** The condition called **Guidance** throughout this repo is implemented by a prompt whose
> header literally reads `CONTEXT:`; the coding scripts retain that verbatim wording so they reproduce
> exactly what was sent to the APIs.

## Reproducing the results

### Requirements
- **Python 3.10+** for the coding scripts (`pip install -r requirements.txt` inside any variant folder).
- **Stata** (tested with StataMP) for `analysis/`; the `.do` files use `estout`, `reghdfe`, `coefplot`.
- **Git LFS** to retrieve the dataset: `git lfs install && git lfs pull`.

### 1. LLM coding (`llm_coding/`)
The scripts document exactly how each coding was produced:
```bash
cd llm_coding/<Study>/<...>/<variant>
pip install -r requirements.txt
cp .env.example .env          # then add OPENAI_API_KEY, GEMINI_API_KEY, DEEPSEEK_API_KEY
export TEST_MODE=true          # small smoke-test slice; set false for a full run
python gpt_coding_replication.py      # plus gemini_/deepseek_ (gpt_coder.py etc. in Timing)
```
API keys are never committed — only `.env.example` templates are included. **Note on inputs:** the scripts
read a `data_encoding_template.csv` of raw messages. A copy is included for the Legitimacy new-sessions
runs (`llm_coding/Legitimacy/llm_code_new_sessions/`); the other studies' input templates are not shipped.
The final merged labels for every coder are in `data/master_dataset.csv`.

### 2. Analysis (`analysis/`, Stata)
Each `comparison_table.do` reads `../../../data/master_dataset.csv`, writes a `comparison_table.tex`, and
renders `comparison_table.jpg`. Run from inside a variant folder:
```bash
cd analysis/LLM_Guidance/simplified
stata-mp -b do comparison_table.do
```
- **simplified** — p-value per coding source, with Match-Sign and Match-Significance columns.
- **extended** — coefficient and p-value per coding source.
- **LLM_Baseline** uses the Base LLM column; **LLM_Guidance** uses the Guidance column (Promises has no
  Guidance variant, so its LLM column falls back to Base — noted in the table).
